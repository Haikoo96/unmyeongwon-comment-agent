운명원 댓글 에이전트 · 제작 의도

광고가 아니라 호기심을 옮기는 댓글

댓글을 쓰는 건 시청자를 연기하는 에이전트이고, 움직여야 할 건 그 댓글을 읽는 다른 시청자입니다. 모든 설계는 이 한 문장에서 출발했습니다.

GitHub 저장소 시연 영상 (2분 5초) 작동 원리 애니메이션

1문제를 이렇게 봤습니다

이 과제의 댓글은 두 사람을 상대합니다. 댓글을 쓰는 쪽은 영상을 본 시청자를 연기하는 에이전트이고, 실제로 움직여야 하는 타깃은 그 댓글을 읽는 다른 시청자입니다.

좋은 댓글의 기준은 "운명원을 잘 홍보했는가"가 아니라 "읽는 사람이 자기 얘기라고 느끼고, 운명원이 궁금해졌는가"입니다.

광고처럼 보이는 순간 효과는 사라집니다. 이 댓글은 추천이 아니라 호기심을 옮겨야 합니다.

2핵심 아이디어: 소구점을 타깃의 삶에 잇기

제품의 소구점을 그대로 말하면 와닿지 않습니다. 타깃이 지금 겪고 있는 삶의 한 장면에 이어 말해야 "내 얘기"가 됩니다. 운명원의 소구점은 "연애 사주를 잘 본다"입니다. 그런데 연애 영상에 이 문장을 그대로 쓰면 광고로 읽힙니다.

연애 고민 영상을 보는 사람에게 필요한 건 사주 자체가 아니라, 끝없이 곱씹는 불확실함을 멈추는 것입니다. 그래서 소구점을 그 결핍의 언어로 바꿨고, 그 언어는 페르소나마다 다릅니다.

페르소나지금 이 사람의 장면운명원으로 이어지는 말
소구점 그대로모든 영상에 같은 문장연애 사주 잘 봐요
썸 타다 읽씹당함새벽에 카톡을 다시 읽으며 "내가 뭘 잘못했지" 곱씹는 중내 탓인지 아닌지라도 알고 싶다
회피형 전 연인에 미련스토리 조회 목록에 그 이름이 있는지 확인하는 중다시 와도 똑같을지 알고 싶다
잘해 주다 지친 30~40대밥값 다 내고 퇴근 동선 맞춰도 답은 "ㅎㅎ 좋아요"결 맞는 사람이 언제 오는지만 알아도 덜 피곤할 것 같다

에이전트가 이 연결을 매번 만들 수 있도록, 페르소나를 삶의 여정으로 그리고 마지막에 운명원으로 가는 다리를 찾게 했습니다.

계기→몸부림→지금 상태→채워지지 않은 욕구→운명원으로 가는 다리

3에이전트를 셋으로 나눈 이유

한 번의 프롬프트로 댓글을 쓰게 하면, 결과가 좋든 나쁘든 왜 그렇게 나왔는지 알 수 없습니다. 역할을 나누면 각 단계의 결과가 화면에 근거로 남고, 어디를 고쳐야 할지 보입니다.

AGENT 1

페르소나 분석가

영상(자막, 없으면 제목·설명)과 인기 댓글을 읽습니다. 먼저 가짜·홍보 댓글을 걸러냅니다. 업체 홍보나 복붙 댓글을 그대로 학습하면 광고 냄새가 증폭되기 때문입니다. 남은 진짜 목소리로 고민 한 줄, 페르소나, 영상 속 장면을 뽑고, 근거가 부족하면 "근거 낮음"으로 표시합니다.
AGENT 2

컨텍스트 헌터

같은 고민을 가진 사람들이 실제로 쓴 커뮤니티 글(블라인드, 네이트판, 여성시대 등)을 웹에서 찾아 읽고, 그 말투와 일상 디테일로 삶의 여정을 그립니다. 언론·매거진 기사는 사람의 언어가 아니라서 제외합니다.
AGENT 3

댓글 작가

영상 속 장면 하나, 페르소나의 처지, 운명원 넛지 하나를 담아 씁니다. 넛지는 소문·질문·다짐 중에서 고르고, 최근 다른 영상에 쓴 초안과 구조가 겹치지 않게 합니다. 자막이 없는 영상에서는 대사를 지어내지 않도록 따옴표 인용을 금지했습니다.

4오케스트레이션은 코드로, 에이전트는 Claude Code로

세 단계의 순서는 항상 같습니다. 그래서 에이전트가 스스로 다음 할 일을 정하는 자율 루프 대신, 순서를 코드로 고정했습니다(app/agents/pipeline.py). 실행이 예측 가능하고, 어느 단계에서 실패했는지 바로 알 수 있습니다.

각 에이전트는 터미널에서 claude -p(Claude Code 헤드리스 모드)로 실행합니다.

  • 구조화된 출력: --json-schema로 각 단계의 결과를 정해진 모양으로 받아 그대로 DB에 저장하고 화면에 보여줍니다.
  • 웹 검색 내장: 컨텍스트 헌터에게만 검색 도구를 열어 실제 커뮤니티 글을 읽게 합니다. 이 단계에는 유튜브 댓글 원문을 넘기지 않아, 댓글 속 지시문이 검색을 조종하지 못하게 했습니다.
  • 키 관리 부담 없음: API 키 대신 Claude 로그인으로 돌아서, 저장소에 비밀 값이 들어갈 여지가 줄어듭니다.

5대시보드는 사람이 쥐는 운전대

댓글만 다는 게 목적이라면 스크립트 하나로 충분합니다. 그런데 이 도구를 매일 쓰는 사람은 마케터입니다. 그래서 대시보드를 AI가 일하고 사람이 승인하는 화면으로 설계했습니다.

  • 왼쪽에서 오른쪽으로: 앞 칸을 하지 않으면 다음 칸이 흐리게 잠겨서, 설명 없이도 순서가 보입니다.
  • 근거를 보여줍니다: 초안만 보여주면 믿고 올리기 어렵습니다. 페르소나, 여정, 근거 댓글, 걸러낸 댓글, 참고한 글을 펼쳐 볼 수 있습니다.
  • 고칠 수 있습니다: 초안을 직접 고치면 규칙 검사가 실시간으로 돌고, 어기면 게시 버튼이 잠깁니다. "댓글만 다시 쓰기"는 페르소나는 그대로 두고 작가만 다시 돌려 약 20초 안에 새 초안을 줍니다.

6게시는 에이전트가 아니라 정해진 코드로

크롬을 열고 타이핑해서 올리는 일에 AI 판단이 들어가면 엉뚱한 곳에 올라갈 위험이 생깁니다. 그래서 게시는 정해진 순서대로만 움직이는 Playwright 코드로 만들었습니다.

여는 중→입력 중→게시 버튼→확인 중→성공 · 직링크 저장
버튼 전 실패 → 다시 시도 가능버튼 후 실패 → 확인 필요 · 영상 잠금

가장 신경 쓴 부분은 중복 게시 방지입니다. 게시 버튼을 누른 뒤에 오류가 나면 댓글은 이미 올라갔는데 기록은 "실패"가 될 수 있고, 다시 누르면 같은 영상에 댓글이 두 개 달립니다. 그래서 버튼 이후의 실패는 "확인 필요"로 따로 기록하고, 사람이 영상에서 확인할 때까지 그 영상을 잠급니다. 성공 판정도 입력창이 아니라 댓글 목록에서 내 댓글을 찾은 경우에만 하고, 그 댓글의 직링크를 저장합니다.

7운영 규칙은 화면이 아니라 코드에서

화면에서 버튼을 숨기는 것만으로는 규칙이 지켜지지 않습니다. 허용 범위, 영상당 1개, 하루 상한, 금지 표현을 모두 서버에서 검사하고, 영상당 1개는 DB 고유 인덱스로 한 번 더 막았습니다. 동시에 두 번 눌러도 둘 다 통과하지 않도록 게시는 한 번에 하나만 돌게 했습니다. "운명원 가봤는데 용하더라" 같은 이용 후기 문장은 사람이 초안을 고쳐 넣어도 서버에서 막힙니다.

8검증

  • 4개 채널의 영상 6개로 파이프라인을 돌려, 영상마다 페르소나와 장면, 넛지 방식이 달라지는 것을 확인했습니다.
  • 다른 모델(Claude Opus, 최대 추론)에게 코드 전체를 독립 리뷰하게 해서 나온 13건을 모두 반영했습니다. 실패 캡처가 찍히지 않던 문제, 중복 게시 가능성, 분석 응답이 다른 영상 화면에 그려지는 경합, API 키가 오류 문구로 노출될 수 있던 문제 등입니다.
  • 실제 유튜브에서 프로필 열기 → 한 글자씩 입력 → 게시 → 목록 확인 → 댓글 직링크 저장까지 끝까지 동작하는 것을 확인했습니다. 시연 영상에 그 과정이 그대로 담겨 있습니다.

9한계와 다음 단계

스레드글 중심이라 삶의 여정 재료로 가장 좋은 소스입니다. Threads API 키워드 검색은 Meta 앱 심사를 받아야 다른 사람의 공개 글이 검색되어 이번에는 제외했습니다. 승인 후 연결만 추가하면 됩니다.
페르소나 여정 라이브러리연애 고민은 읽씹, 재회, 짝사랑 같은 패턴 몇십 개로 모입니다. 재료를 미리 쌓아 두면 분석 시간과 비용이 줄어듭니다(snippets 테이블).
남은 가점 항목'연애' 키워드로 뜨기 직전 영상 찾기와 프로필 자동 배정은 아직 구현하지 않았습니다.
플랫폼 정책시청자를 연기하는 홍보 댓글은 유튜브 스팸 정책과 맞닿아 있습니다. 하루 상한, 영상당 1개, 이용 후기 금지, 사람 승인을 안전장치로 두었고, 실제 운영이라면 광고임을 밝히는 방식도 함께 검토해야 한다고 봅니다.
